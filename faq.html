💾 Lưu trữ & dữ liệu

+ Dữ liệu của tôi được lưu ở đâu?

Toàn bộ dữ liệu (thể loại, truyện) được lưu trong localStorage của trình duyệt bạn đang dùng, dưới 2 key:

  • epub_editor_data_v1 — dữ liệu chính (JSON)
  • epub_editor_active_cat — chỉ số thể loại đang chọn

Nghĩa là dữ liệu nằm trên máy bạn, không gửi lên server nào cả. Mọi thao tác Thêm/Sửa/Xoá đều được lưu ngay lập tức (không cần bấm Save toàn cục).

+ Tôi mở trên máy khác / trình duyệt khác, có thấy dữ liệu không?

Không. localStorage là per-browser, per-device. Mở trên Chrome máy A ≠ Chrome máy B ≠ Firefox máy A.

Để có dữ liệu trên máy mới, bạn cần:

  • Bấm 🔄 Đồng bộ để kéo từ server remote (nếu server có sẵn dữ liệu bạn muốn).
  • Hoặc 📥 Nhập file JSON bạn đã xuất trước đó.
💡 Mẹo: Trước khi đổi máy, bấm 📤 Xuất file để backup. Sang máy mới, 📥 Nhập lại.
+ Bấm 🗑 Reset có hoàn tác được không?
⚠️ Không. Reset xoá sạch toàn bộ dữ liệu trong localStorage, không thể khôi phục.

Trước khi Reset, bắt buộc nên:

  1. Bấm 📤 Xuất file → lưu listepub.txt về máy.
  2. Hoặc 📋 Copy → paste vào Notepad/Google Docs.

Sau khi Reset xong, bạn có thể 📥 Nhập lại file cũ nếu đổi ý.

+ Làm sao để backup dữ liệu định kỳ?

Có 2 cách:

  • Thủ công: Định kỳ bấm 📤 Xuất file → đặt tên có ngày tháng (VD: listepub-2024-10-04.txt) → lưu vào Google Drive/Dropbox.
  • Tự động: Không có tích hợp sẵn, nhưng bạn có thể dùng extension như LocalStorage Manager để export toàn bộ localStorage định kỳ.
Lưu ý: Nếu bạn dùng chế độ ẩn danh (Incognito), localStorage sẽ bị xoá khi đóng tab. Không dùng Incognito cho công việc thật.
+ Tôi muốn sao chép toàn bộ dữ liệu sang máy mới. Làm sao?

3 bước đơn giản:

  1. Máy cũ: Bấm 📤 Xuất file → nhận listepub.txt.
  2. Chuyển file qua máy mới (USB, email, cloud, Zalo…).
  3. Máy mới: Mở editor → bấm 📥 Nhập → tab 📁 Chọn file → kéo thả file → 📥 Nhập.

Xong. Toàn bộ thể loại và truyện sẽ được gộp vào (không trùng).

🔄 Đồng bộ

+ Đồng bộ tự động hoạt động như thế nào? SYNC

Mỗi lần bạn mở trang, hệ thống tự động:

  1. Fetch JSON từ server remote (URL cấu hình trong REMOTE_DATA_URL).
  2. So sánh với dữ liệu trong localStorage của bạn.
  3. Gộp thông minh: chỉ thêm cái mới, không xoá cái cũ, không ghi đè.
  4. Hiện toast báo cáo: +N truyện, +M thể loại nếu có gì mới.

Ngoài ra, bạn có thể bấm nút 🔄 Đồng bộ trên header bất kỳ lúc nào để force refresh (thêm ?_t=timestamp để phá cache).

+ Đồng bộ có ghi đè / xoá dữ liệu tôi đã tự thêm không?
✅ Không. Đồng bộ chỉ thêm, không bao giờ xoá hay ghi đè.

Cụ thể:

  • Thể loại trùng tên (không phân biệt hoa/thường) → gộp truyện vào thể loại cũ.
  • Thể loại chưa có → thêm mới.
  • Truyện trùng URL hoặc trùng tên → bỏ qua, giữ bản cũ.
  • Nếu bản cũ thiếu author/description/cover mà bản mới có → tự bổ sung.

Truyện bạn tự thêm mà server không có → vẫn giữ nguyên.

+ Tôi muốn đổi server đồng bộ sang server riêng. Làm sao?

Mở file index.html bằng Notepad/VS Code, tìm biến REMOTE_DATA_URL trong block CONFIG:

var REMOTE_DATA_URL = 'https://your-server.com/path/listepub.txt';

Thay bằng URL của bạn, lưu file, xong.

💡 Yêu cầu: URL phải trả về JSON đúng schema (xem mục Cấu trúc dữ liệu trong README). Server cần bật CORS cho domain của bạn.
+ Server remote bị lỗi / sập / không có mạng thì sao?

Không sao cả. Editor vẫn hoạt động bình thường với dữ liệu trong localStorage. Chỉ có tính năng đồng bộ là tạm ngưng.

Khi mở trang, nếu fetch lỗi sẽ có cảnh báo trong Console:

[Editor] Remote fetch fail: ...

Nhưng giao diện không văng, không ảnh hưởng dữ liệu. Khi server hoạt động lại, bấm 🔄 Đồng bộ để thử lại.

+ Tôi muốn tự host dữ liệu để chia sẻ cho nhiều người? HOT

Các bước:

  1. Chuẩn bị file JSON theo đúng schema (xem README mục Cấu trúc dữ liệu JSON).
  2. Upload file lên chỗ public:
    • GitHub raw — push file vào repo, lấy URL raw.githubusercontent.com/...
    • Cloudflare Worker / R2 — tạo worker trả JSON.
    • Netlify/Vercel — đặt file trong thư mục public/.
    • Bất kỳ CDN nào có CORS mở.
  3. Sửa REMOTE_DATA_URL trong index.html thành URL của bạn.
  4. Deploy lại editor.

Ai mở editor cũng sẽ tự đồng bộ từ server bạn.

⚠️ Nhớ bật CORS: Nếu server không cho phép domain của editor, fetch sẽ fail. Thêm header: 
Access-Control-Allow-Origin: *

📤📥 Xuất & Nhập

+ Làm sao chia sẻ danh sách truyện cho bạn bè? HOT

Có 2 cách nhanh:

Cách 1 — Xuất file (khuyến nghị)

  1. Bấm 📤 Xuất file → tải về listepub.txt.
  2. Gửi file qua Zalo / Messenger / Email / Google Drive.
  3. Bạn bè mở editor → 📥 Nhập → tab 📁 Chọn file → kéo thả file → OK.

Cách 2 — Copy clipboard (nhanh gọn)

  1. Bấm 📋 Copy → JSON vào clipboard.
  2. Paste vào chat / email / ghi chú.
  3. Bạn bè copy đoạn đó → mở editor → 📥 Nhập → tab 📋 Dán JSON → paste → OK.
💡 Khi nào dùng cách nào? File thì gọn gàng, chuyên nghiệp, phù hợp gửi qua email. Clipboard thì nhanh, tiện chat, nhưng JSON dài có thể bị cắt khi gửi qua một số app.
+ Tôi nhập file từ bạn, có ghi đè dữ liệu của tôi không?
✅ Không. Từ bản 1.1, nhập luôn luôn GỘP, không bao giờ ghi đè.

Quy tắc gộp:

  • Thể loại trùng tên (không phân biệt hoa/thường) → gộp truyện vào.
  • Thể loại mới → thêm vào.
  • Truyện trùng URL hoặc trùng tên (case-insensitive) → bỏ qua, giữ bản cũ.
  • Truyện cũ thiếu metadata → bổ sung từ bản mới.

Kết quả sẽ hiện toast:

  • ✅ 📥 Đã gộp: +N truyện, +M thể loại — có dữ liệu mới.
  • ✓ Không có gì mới (tất cả đã tồn tại) — trùng hết.

Muốn GHI ĐÈ hoàn toàn?

  1. Bấm 🗑 Reset trước để xoá sạch.
  2. Rồi mới 📥 Nhập file mới.
+ Tôi có thể sửa JSON bằng tay trước khi nhập không?

Được. Đây là cách tốt để chỉnh số lượng lớn:

  1. 📤 Xuất file → mở bằng Notepad / VS Code.
  2. Sửa trực tiếp (thêm thể loại, sửa tên, thêm truyện…).
  3. Lưu file → 📥 Nhập lại (nhớ Reset trước nếu muốn thay thế hoàn toàn).
⚠️ Lưu ý: Phải giữ đúng cấu trúc JSON (dấu phẩy, ngoặc kép…). Sai 1 dấu là hỏng cả file. Nên dùng editor có syntax highlight và validate JSON.

🛠 Nhập liệu & Đường dẫn

+ Auto-fill URL hoạt động ra sao?

Hệ thống slug hoá tên truyện (bỏ dấu, viết thường, bỏ ký tự đặc biệt) rồi ghép vào:

epub/<slug>.epub   (ebook)
img/<slug>.jpg    (cover)

Ví dụ:

  • Bàn Long → epub/banlong.epub + img/banlong.jpg
  • Thiên Long Bát Bộ → epub/thienlongbatbo.epub
  • Ỷ Thiên Đồ Long Ký → epub/ythiendolongky.epub

Cách kích hoạt:

  • Tự động: Gõ tên → chờ 400ms → URL tự điền (nếu URL đang trống hoặc vẫn là auto-fill).
  • Thủ công: Bấm ✨ Auto-fill từ tên ở chân modal → ghi đè luôn.
Lưu ý: Nếu bạn tự tay sửa URL khác đi, hệ thống sẽ không ghi đè nữa. Muốn auto lại → bấm nút ✨.
+ Tại sao ảnh bìa không hiện?

Kiểm tra theo thứ tự:

  1. URL ảnh có đúng không? — Mở URL đó trong tab mới xem có ảnh không.
  2. Base URL có đúng không? — Xem biến DEFAULT_RAW_BASE. Nếu bạn dùng short path img/abc.jpg, hệ thống sẽ ghép BASE + img/abc.jpg.
  3. File có tồn tại trên server không? — Kiểm tra trong repo.
  4. CORS? — Nếu host ảnh không cho phép cross-origin, browser sẽ chặn.
  5. Tên file đúng chưa? — Slug hoá đôi khi làm sai. VD: Ỷ Thiên → ythien (không phải y thien).

Nếu ảnh lỗi, hệ thống sẽ hiện chữ cái đầu tên truyện trên nền tối (fallback đẹp).

+ Có giới hạn số lượng thể loại / truyện không?

Trên lý thuyết: không. Nhưng có giới hạn thực tế:

  • localStorage giới hạn ~5-10 MB tuỳ trình duyệt. Mỗi truyện chiếm ~300 byte → ~15.000-30.000 truyện là thoải mái.
  • Render: Nếu một thể loại có hơn 500 truyện, cuộn có thể hơi lag (do render hết 1 lượt). Chia nhỏ thể loại sẽ mượt hơn.
💡 Khuyến nghị: Chia thể loại hợp lý (< 200 truyện/thể loại) để dễ quản lý và mượt UI.
+ Nếu tên thể loại bị trùng thì sao?

Tuỳ trường hợp:

  • Trùng do đồng bộ/nhập: Hệ thống tự động gộp vào thể loại cũ (so sánh case-insensitive: Kim Dung = kim dung = KIM DUNG).
  • Bạn tự thêm 2 thể loại cùng tên bằng nút + Thêm: Hệ thống không chặn — bạn sẽ có 2 mục cùng tên. Cần xoá bằng tay (sửa JSON).
+ Truyện trùng tên nhưng khác file (URL) thì xử lý sao?

Trong đồng bộ và nhập, quy tắc là: trùng URL HOẶC trùng tên → coi là cùng 1 truyện.

Nên nếu bạn có 2 truyện tên Bàn Long nhưng 1 file banlong.epub, 1 file banlong_v2.epub → hệ thống sẽ coi là trùng và chỉ giữ bản đầu.

⚠️ Cách xử lý: Đặt tên khác nhau rõ ràng, VD: Bàn Long (bản cũ) và Bàn Long (tái bản).

🌐 Kỹ thuật

+ Tôi mở file bằng file:// (nhấp đôi file html) — có dùng được không?

Được, hầu hết tính năng hoạt động bình thường: thêm/sửa/xoá, lưu localStorage, xuất/nhập file.

Tuy nhiên, một số browser có thể chặn:

  • fetch remote (CORS không cho file://) → đồng bộ tự động có thể fail. Nút 🔄 vẫn bấm được nhưng có thể báo lỗi.
  • Clipboard API (nút Copy) → có thể cần HTTPS.
💡 Khuyến nghị: Muốn dùng đầy đủ tính năng (đồng bộ, copy), host editor qua HTTPS. Miễn phí với GitHub Pages, Netlify, Vercel.
